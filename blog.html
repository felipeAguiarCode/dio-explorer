      Consulta rápida

        Você publicou uma aplicação feita com ajuda de IA e não tem certeza se ela está segura? Estes três prompts funcionam em qualquer assistente que leia o seu projeto, como Claude Code, Codex ou Copilot. Rode um de cada vez, na pasta raiz do repositório.

        Os prompts pedem só leitura e relatório. Deixe o assistente corrigir depois que você ler o que ele encontrou.

        1. Segredos expostos

        A falha mais comum: uma chave de API ou senha que foi parar no código ou no histórico do Git.

        Faça uma auditoria de segredos neste repositório, sem alterar nenhum arquivo.

Procure por chaves de API, tokens, senhas, strings de conexão de banco
e chaves privadas em:
1. todos os arquivos do projeto, incluindo configurações e exemplos;
2. o histórico do Git (git log -p), mesmo em arquivos já apagados;
3. arquivos .env que estejam versionados ou fora do .gitignore;
4. código de front-end que seja enviado ao navegador.

Para cada achado, informe: arquivo e linha, tipo de segredo, se ainda
parece válido e o que fazer (revogar, trocar, mover para variável de
ambiente). Nunca escreva o segredo inteiro na resposta: mostre só os
4 primeiros caracteres.

        Se encontrar algo: revogue e gere a chave de novo no serviço de origem. Apagar do código não basta, porque ela continua no histórico.

        2. Código e dependências suspeitos

        Aqui a pergunta é outra: existe algo no projeto que você não escreveu e não sabe o que faz?

        Revise este projeto em busca de sinais de comprometimento, sem alterar
nenhum arquivo.

Verifique:
1. dependências: pacotes com nome parecido com o de pacotes famosos,
   pacotes pouco conhecidos, versões sem trava e scripts de instalação
   (postinstall e similares);
2. código ofuscado ou codificado: eval, Function, base64 longo, strings
   montadas em pedaços, arquivos minificados fora da pasta de build;
3. chamadas de rede para endereços que não fazem parte do produto;
4. comandos de sistema, leitura de variáveis de ambiente ou de arquivos
   sensíveis sem motivo claro;
5. mudanças recentes no Git que não combinam com o restante do projeto.

Liste cada item com arquivo, linha, por que é suspeito e o nível de
risco (alto, médio ou baixo). Diga também o que você verificou e não
encontrou problema.

        Se encontrar algo: não apague de imediato. Descubra quando entrou (git log no arquivo) e o que ele pode ter acessado.

        3. Acessos e portas abertas

        Por fim, o que um visitante mal-intencionado conseguiria fazer usando a aplicação do jeito que ela está.

        Analise esta aplicação do ponto de vista de um atacante, sem alterar
nenhum arquivo e sem executar ataques.

Mapeie:
1. todas as rotas e endpoints, e quais funcionam sem login;
2. rotas que confiam em dados enviados pelo cliente para decidir quem
   é o usuário ou o que ele pode ver (id na URL, papel no corpo);
3. entradas que chegam ao banco, ao sistema de arquivos ou ao HTML sem
   validação (injeção de SQL, de comandos e XSS);
4. regras de acesso do banco e do armazenamento de arquivos que estejam
   públicas;
5. configurações inseguras: CORS aberto, modo debug ligado, mensagens
   de erro que mostram detalhes internos, uploads sem limite.

Entregue uma tabela com: ponto fraco, onde está, como seria explorado
em uma frase e a correção recomendada, ordenada do mais grave ao menos
grave.

        Se encontrar algo: comece pelo que dá acesso a dados de outras pessoas. É o que mais causa prejuízo.

        O que esses prompts não fazem

        • Não veem o que está fora do repositório: servidor, painel da nuvem e logs de acesso precisam ser conferidos à parte.
        • Podem errar para os dois lados: apontar um problema que não existe ou deixar um passar. Trate o relatório como uma lista do que investigar.
        • Não substituem ferramentas próprias de segurança nem a revisão de alguém da área em aplicações com dados sensíveis.

        Próximo: O que é um LLM e como ele funciona

        Git é um sistema que guarda o histórico do seu código. Com ele você salva versões, volta no tempo quando algo quebra e trabalha em equipe sem um sobrescrever o trabalho do outro. Este guia cobre o essencial, na ordem em que você vai precisar.

        1. Instalar

        Windows

        Baixe o instalador em git-scm.com/downloads e avance com as opções padrão. Ou, pelo terminal:

        winget install --id Git.Git -e

        macOS

        brew install git

        Linux (Debian e Ubuntu)

        sudo apt update
sudo apt install git

        Confira se deu certo:

        git --version

        2. Configurar (uma vez só)

        O Git assina cada versão com seu nome e e-mail. Use o mesmo e-mail da sua conta do GitHub.

        git config --global user.name "Seu Nome"
git config --global user.email "voce@exemplo.com"
git config --global init.defaultBranch main

        Para ver o que ficou configurado:

        git config --list

        3. Começar um projeto

        Para transformar uma pasta em um repositório:

        cd meu-projeto
git init

        Para baixar um repositório que já existe:

        git clone https://github.com/usuario/repositorio.git

        4. O ciclo do dia a dia

        Quase tudo no Git é este ciclo: ver o que mudou, escolher o que entra e salvar uma versão.

        git status                 # o que mudou?
git add arquivo.txt        # escolhe um arquivo
git add .                  # ou escolhe tudo
git commit -m "Explica o que foi feito"

        Um commit é uma versão salva. Escreva mensagens curtas que digam o que mudou, como "Corrige cálculo do frete".

        git log --oneline          # histórico resumido
git diff                   # mudanças ainda não escolhidas

        5. Branches

        Uma branch é uma linha paralela de trabalho. Você mexe nela sem afetar a main e junta quando terminar.

        git switch -c minha-feature   # cria e entra na branch
git switch main               # volta para a main
git merge minha-feature       # junta a branch na main
git branch -d minha-feature   # apaga a branch já usada

        6. Trabalhar com o GitHub

        git remote add origin https://github.com/usuario/repositorio.git
git push -u origin main    # envia pela primeira vez
git push                   # envia os próximos commits
git pull                   # traz o que há de novo

        7. Ignorar arquivos

        Crie um arquivo .gitignore na raiz do projeto com o que não deve ir para o repositório:

        node_modules/
.env
*.log

        8. Desfazer

        git restore arquivo.txt            # descarta mudanças não salvas no arquivo
git restore --staged arquivo.txt   # tira o arquivo do próximo commit
git commit --amend                 # corrige o último commit
git revert <id-do-commit>          # cria um commit que desfaz outro
git stash                          # guarda as mudanças para depois
git stash pop                      # traz de volta
        Prefira git revert a apagar histórico. Ele desfaz sem reescrever o que outras pessoas já baixaram.

        Cola rápida

        Quero…Comando
        Ver o estadogit status
        Salvar uma versãogit add . e git commit -m "…"
        Ver o históricogit log --oneline
        Criar uma branchgit switch -c nome
        Juntar uma branchgit merge nome
        Enviar para o GitHubgit push
        Atualizar minha cópiagit pull
        Desfazer um commitgit revert <id>

        Próximo: Como instalar o VS Code

        O Visual Studio Code é um editor de código gratuito da Microsoft. É leve, funciona em Windows, macOS e Linux e serve para praticamente qualquer linguagem.

        1. Baixar e instalar

        Acesse code.visualstudio.com e clique em Download. O site já oferece a versão do seu sistema.

        Windows

        Abra o instalador e avance. Na tela de tarefas adicionais, marque Adicionar ao PATH e as duas opções Abrir com Code. Ou instale pelo terminal:

        winget install --id Microsoft.VisualStudioCode -e

        macOS

        Abra o arquivo baixado e arraste o Visual Studio Code para a pasta Aplicativos. Ou:

        brew install --cask visual-studio-code

        Linux

        sudo snap install code --classic

        Em Debian e Ubuntu você também pode baixar o arquivo .deb no site e instalar com dois cliques.

        2. Abrir um projeto

        No VS Code você trabalha com pastas. Use Arquivo → Abrir Pasta ou, no terminal, dentro da pasta do projeto:

        code .

        3. Cinco ajustes para o primeiro dia

        1. Português: abra as extensões (Ctrl+Shift+X), procure por "Portuguese (Brazil) Language Pack" e instale.
        2. Salvar sozinho: em Arquivo, marque Salvamento Automático.
        3. Formatar ao salvar: abra as configurações (Ctrl+,), procure "format on save" e ative.
        4. Prettier: instale a extensão "Prettier - Code formatter" para o código ficar padronizado.
        5. Extensão da sua linguagem: Python, Java, C# e outras têm extensões oficiais com autocompletar e depuração.

        4. Atalhos que mais economizam tempo

        AtalhoO que faz
        Ctrl+PAbre qualquer arquivo pelo nome
        Ctrl+Shift+PPaleta de comandos: tudo o que o editor faz
        Ctrl+' (ou Ctrl+`)Abre o terminal integrado
        Ctrl+/Comenta a linha
        Alt+↑ e Alt+↓Move a linha para cima ou para baixo
        Ctrl+DSeleciona a próxima ocorrência da palavra

        No macOS, troque Ctrl por Cmd.

        Próximo: A linha do tempo da inteligência artificial

        A inteligência artificial parece ter surgido de repente, mas é uma história de mais de sete décadas, com períodos de euforia e de frustração. Estes são os marcos que valem a pena conhecer.

        As ideias (1950 a 1969)

        • 1950Alan Turing publica o artigo que pergunta se máquinas podem pensar e propõe um teste: se você conversa com uma máquina e não percebe que é uma máquina, ela passou.
        • 1956Um encontro de pesquisadores em Dartmouth, nos Estados Unidos, dá nome à área: inteligência artificial.
        • 1958Frank Rosenblatt apresenta o Perceptron, um neurônio artificial simples que aprende com exemplos. É o avô das redes neurais.
        • 1966ELIZA, um dos primeiros chatbots, simula um terapeuta repetindo as frases do usuário em forma de pergunta.

        Os invernos (1970 a 1990)

        As promessas eram maiores que os computadores da época. O dinheiro para pesquisa secou duas vezes, nos períodos que ficaram conhecidos como invernos da IA. No meio deles, em 1986, popularizou-se o método que permite treinar redes neurais com várias camadas, a retropropagação. A ideia estava certa, mas faltavam dados e poder de processamento.

        As máquinas começam a vencer (1997 a 2016)

        • 1997O Deep Blue, da IBM, vence o campeão mundial de xadrez Garry Kasparov.
        • 2012A rede neural AlexNet vence com folga uma competição de reconhecimento de imagens usando placas de vídeo. Começa a era do aprendizado profundo.
        • 2016O AlphaGo, da DeepMind, derrota Lee Sedol no Go, um jogo considerado difícil demais para computadores.

        A era dos modelos de linguagem (2017 em diante)

        • 2017Pesquisadores do Google publicam "Attention Is All You Need" e apresentam o Transformer, a arquitetura por trás dos modelos atuais.
        • 2018Surgem BERT e GPT, que mostram o poder de pré-treinar um modelo em muito texto e depois adaptá-lo a tarefas.
        • 2020O GPT-3 escreve textos longos e coerentes a partir de uma instrução simples.
        • 2022Geradores de imagem como Stable Diffusion e DALL·E 2 se popularizam. Em novembro, o ChatGPT leva a IA generativa ao grande público.
        • 2023 em dianteOs modelos passam a entender imagem, áudio e código, e ganham ferramentas: navegam, executam programas e trabalham como agentes em tarefas de vários passos.

        O que tirar disso

        Três coisas se repetem nessa história: as ideias costumam surgir décadas antes de funcionarem, os saltos acontecem quando dados e processamento alcançam a teoria, e toda onda de euforia é seguida por ajustes de expectativa. Quem entende o básico atravessa melhor as duas fases.

        Próximo: O que é um LLM

        LLM é a sigla em inglês para modelo de linguagem de grande porte. É o tipo de inteligência artificial por trás do ChatGPT, do Claude e do Gemini. A definição mais útil cabe em uma linha:

        Um LLM é um programa treinado para prever qual é o próximo pedaço de texto.

        Todo o resto, de escrever código a resumir um contrato, sai dessa habilidade repetida milhares de vezes.

        Tokens: as peças do texto

        O modelo não lê letras nem palavras inteiras. Ele quebra o texto em tokens, que são pedaços de palavras. "Programação" pode virar "Program" e "ação". É em tokens que se medem o tamanho de uma conversa, o limite do modelo e o custo de uso.

        Treinamento: aprender lendo

        No treinamento, o modelo recebe uma quantidade enorme de texto com o final escondido e tenta adivinhar o que vem depois. A cada erro, seus bilhões de ajustes internos, os parâmetros, são corrigidos um pouco. Depois de muitas repetições ele aprende gramática, fatos, estilos e até formas de raciocinar, porque tudo isso ajuda a acertar a próxima palavra.

        Contexto: a memória de trabalho

        O modelo só enxerga o que está na janela de contexto: suas instruções, a conversa até ali e os arquivos que você enviou. Ele não se lembra de conversas anteriores a menos que o aplicativo coloque esse histórico de volta no contexto. Se algo importante não está lá, para o modelo não existe.

        Temperatura: quanta variação

        Ao escolher o próximo token, o modelo tem várias opções prováveis. A temperatura controla o quanto ele arrisca: baixa, ele escolhe quase sempre a opção mais provável e fica previsível; alta, ele varia mais e fica criativo, com mais chance de errar.

        Alucinação: quando soa certo e está errado

        Como o objetivo é produzir texto plausível, o modelo pode inventar um dado, uma citação ou uma função que não existe, com toda a segurança. Três hábitos reduzem o problema:

        • Dê a fonte: cole o documento ou o código e peça a resposta com base nele.
        • Peça que ele diga quando não souber.
        • Confira o que importa: números, nomes, links e comandos antes de executar.

        Como dar ao modelo o que ele não sabe

        TécnicaO que fazQuando usar
        PromptInstruções e exemplos na própria conversaSempre. É o primeiro passo
        RAGBusca trechos nos seus documentos e os coloca no contextoPerguntas sobre dados seus ou recentes
        Ajuste finoTreina o modelo um pouco mais com seus exemplosUm estilo ou formato muito específico
        Ferramentas e agentesO modelo chama programas: busca, calculadora, terminalTarefas de vários passos

        Um bom pedido tem quatro partes

        1. Contexto: quem vai ler e para quê.
        2. Tarefa: o que você quer, com um verbo claro.
        3. Material: os dados ou o código em que ele deve se basear.
        4. Formato: como a resposta deve vir, por exemplo uma lista de cinco itens.

        Quem entende que o modelo é um previsor de texto com uma janela de contexto escreve pedidos melhores e desconfia na hora certa. É o que separa usar a ferramenta de depender dela.

        Próximo: Cheatsheet de Docker

        Imagens

        docker pull nginxBaixa uma imagem
        docker imagesLista as imagens baixadas
        docker build -t meu-app .Cria uma imagem a partir do Dockerfile da pasta
        docker rmi <imagem>Apaga uma imagem

        Containers

        docker run -d -p 8080:80 --name web nginxCria e inicia em segundo plano, ligando a porta 8080 do seu computador à 80 do container
        docker psLista os que estão rodando
        docker ps -aLista todos, inclusive parados
        docker stop webPara o container
        docker start webInicia de novo
        docker rm webApaga o container

        Olhar por dentro

        docker logs -f webAcompanha os logs ao vivo
        docker exec -it web shAbre um terminal dentro do container
        docker inspect webMostra todos os detalhes
        docker statsUso de CPU e memória

        Dados e variáveis

        -v meus-dados:/var/lib/dadosGuarda os dados em um volume, que sobrevive ao container
        -v "$(pwd)":/appEspelha a pasta atual dentro do container
        -e CHAVE=valorDefine uma variável de ambiente
        --env-file .envCarrega as variáveis de um arquivo
        docker volume lsLista os volumes

        Dockerfile mínimo

        FROM node:22-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
EXPOSE 3000
CMD ["npm", "start"]

        Compose

        docker compose up -dSobe tudo o que está no compose.yaml
        docker compose up -d --buildSobe reconstruindo as imagens
        docker compose psLista os serviços
        docker compose logs -fLogs de todos os serviços
        docker compose downPara e remove os containers
        docker compose down -vRemove também os volumes

        Limpar

        docker system dfMostra quanto espaço o Docker ocupa
        docker system pruneApaga containers parados, redes e imagens sem uso
        docker compose down -v e docker system prune apagam dados. Confira antes de rodar.
